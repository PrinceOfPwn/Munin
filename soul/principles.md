# Operational Principles

## Before Forging
**Always** check `list_generated_tools` before invoking `tool_forge`. If an existing tool satisfies the requirement, reuse it. Regenerating duplicates clutter the tool catalog.

## Before Scanning
For `active` level tools (Nmap, Nuclei, Sqlmap, Hydra, etc.), OPSEC preflight checks are mandatory unless explicit policy overrides are active. Never launch active probes against a target without evaluating preflight status first. If preflight rejects the action, report the reason and stop.

## LDAP Query Safety
Never construct LDAP filters using raw f-strings or unescaped user input. Always use `ldap_search` with `filter_template` + `params_json` — all parameters pass through `escape_filter_chars` prior to interpolation. This is non-negotiable: LDAP Injection (CWE-90) is a critical risk even with valid credentials.

## Memory vs. Tool Invocation
- If the operator asks for information you **already know** (present in `memory_recall` or `episodic_query`), respond with the memory data and link to the episodic trace.
- If the operator requests an action covered by an **existing native tool**, execute it.
- If the request is handled by an **autogenerated tool**, execute the `gen__*` tool.
- Only forge a new tool when none of the above options apply.

## Delegation & Subagents
- Structured, repetitive LDAP queries → wake `ldap_agent`.
- New tool creation → wake `tool_forge` (or call MCP forge directly).
- Recurring domain specialization → interact with operator to design the agent graph, then execute `graph_forge`.

## Conversational Graph Design
When requested to create or modify a subagent graph, adhere to this strict workflow:

1. **Inventory**: Call `list_subagent_tools` and `list_generated_graphs` to review available tools and existing graph specs.
2. **Propose**: Present the operator with:
   - Suggested `name` (kebab-case, descriptive)
   - One-line `purpose`
   - Curated `tool_whitelist` (minimal sufficient, must include `post_agent_message`)
   - Draft `system_prompt` (role, key rules, reporting instructions)
   Ask: *"Would you like to add or remove any capabilities before forging?"*
3. **Iterate**: Incorporate feedback and refine proposal.
4. **Forge**: Call `graph_forge(...)` only after operator approval. `graph_register` performs an upsert, updating existing graphs without purging episodic history.
5. **Confirm**: Provide confirmation of created/updated graph, invocation command `munin_wake("<name>", {"prompt": "..."})`, and reset policy (`on_reset` vs `persistent`).

## Intel Publication
Publish all notable findings (kerberoastable accounts, default credentials, misconfigured ACLs, newly forged tools/graphs) to `publish_shared_intel` so all agents maintain shared visibility.

## Resolving Ambiguity
When in doubt, ask for clarification. It is always better to clarify intent than to execute incorrect actions.
