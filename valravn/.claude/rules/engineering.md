# 工程铁律

管辖一切工作：代码、配置、渗透工具调用、payload 构造、报告撰写、漏洞赏金狩猎、红队行动。无例外。

## 1. 先思后动

不臆断。不藏疑。亮出权衡。

- 实现前显式声明假设。不确定就问。
- 多种解释并存时，全部呈现——不暗中选一种。
- 有更简方案，直说。该顶回就顶回。
- 不清楚就停。指出困惑点。发问。

**渗透 / 赏金：** 目标行为含糊（漏洞还是设计？）时，声明歧义，双假设并测。

**红队：** 先锁定目标（数据外泄、驻留、横移），再选工具。错工具 = 被发现。

## 2. 简约至上

最小可行解。零投机。

- 不做未要求的功能。
- 不为一次性代码造抽象。
- 不要未被请求的"灵活性"或"可配置性"。
- 不为不可能场景写错误处理。
- 200 行能压到 50 行，重写。

**渗透：** 一次智能调用胜过五次啰嗦调用。`smart_analyze` 优于 5 次单独分析。3 发精准 payload 优于 20 发喷射。

**赏金：** 一个确认的 critical > 十个未验证的 medium。深度优先于广度。证明影响，不列异常。

**红队：** 最小足迹。一发干净利用 > 嘈杂扫描。隐蔽是特性。

## 3. 外科手术式改动

只碰必须碰的。只清理自己的烂摊子。

**改代码时：**
- 不"顺手优化"邻近代码、注释或格式。
- 不重构没坏的东西。
- 沿用既有风格，即便你会换种写法。
- 发现无关死代码，提一句——别删。

**改动产生孤儿时：**
- 移除因你改动而失去引用的 import / 变量 / 函数。
- 不删既有死代码，除非被要求。

**检验标准：** 每一行改动都能追溯到用户请求。

**渗透：** 不测当前目标之外的端点。不重测已覆盖参数。探测前先 `load_target_intel(domain, "coverage")`。

**红队：** 每个动作都推进 kill chain。不服务于利用的侦察 = 浪费的噪声预算。

## 4. 目标驱动执行

定义成功标准。循环到验证通过。

**把任务转为可验证目标：**
- "加校验" → 为非法输入写测试，再让测试通过
- "修 bug" → 写复现测试，再让它通过
- "测 SQLi" → 建立基线、发包、量 delta、用 replay 验证
- "提权到 admin" → 识别权限边界、构造绕过、验证提权

**多步任务，简述计划：**
```
1. [步] -> 验证: [检查]
2. [步] -> 验证: [检查]
3. [步] -> 验证: [检查]
```

强成功标准让你独立循环。弱标准（"让它能跑"）需要澄清——去问。

**渗透：** 每个探针都有假设和验证步骤。"我预期 500 + SQL error"，不是"扔几个 payload 看看"。

**赏金：** 目标是带验证影响的报告。倒推：triager 需要什么证据？收集之，再写。

**红队：** 目标是 objective（flag、数据、访问）。每个动作要么推进它，要么为下一步取情报。卡 3 轮就 pivot。
