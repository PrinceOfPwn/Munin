# Munin 完整手册

[English](../en/handbook.md) · [Español](../es/handbook.md) · [Português BR](../pt-BR/handbook.md)

## 概览

Munin 是一个由操作员治理、面向自主安全行动的持久化运行时。它整合 Discord 操作员适配器
（稳定操作面）、认证 API、MCP、持续开发的 Web GUI、LangGraph 执行、持久化事件、
checkpoint、人工审批、实时能力组合、Hugin 知识和 Valravn 侦察。

v1.1.0 的已验证配置是 **适配器 Discord + GitHub Actions + DeepSeek V4-Flash**。Web GUI 是
长期目标界面，但在实时会话前端 bug 修复通过前视为维修状态；仅限 GUI 的说法视为未验证。
其他组合可能可用，但在明确记录之前均视为实验性配置。

## 核心模型

Munin 将知识、权限、执行和证据分离。知识可以建议路线；只有服务器策略和操作员范围能够
授权执行。工具负责行动，事件和工件负责保存发生过的事实。

## 接口

Discord 是 v1.1.0 的稳定操作面：状态、命令、线程与审批。Web GUI 仍在积极开发。
`/api/*` 提供认证操作，`/mcp/` 暴露实时能力。任何客户端都不拥有独立权限。

## 运行、事件与恢复

每个会话拥有稳定 thread。运行使用可续租 lease。事件可重放，checkpoint 保存可执行状态。
进程故障后，安全恢复会继续同一 thread，而不是让模型重建历史。待审批操作保持暂停。

## 运行模式

- **Standard：** 每个操作单独审批。
- **YOLO：** 在可信范围内减少常规审批。
- **GOAL：** 持久化目标与 TODO。
- **BEAST：** 更深规划与受控预算的专家委派。

所有模式都保留审计、关键审批、秘密脱敏和服务器策略。

## 能力系统

实时注册表可以包含原生工具、Valravn、已审核 skill、受限专家、autonomy kernel 和
`gen__*` 能力。运行时发现是权威来源。文件或 skill 不会因为存在而自动获得执行权限。

## Hugin 与 Valravn

Hugin 提供带来源的被动知识。Valravn 收集 IOC、CVE、资产、历史 Web、路由、暗网和浏览器
证据。两者在针对已授权目标完成验证前都属于不可信外部输入。

## Soul 配置

仓库内 Soul 是针对 CTF 和实验室的特定角色化配置，不是推荐默认值。生产和防御环境应通过
`soul_propose_edit` 与人工审核采用中性或组织专属配置。Soul 永远不能授予权限、工具或范围。

## 操作检查表

1. 确认书面授权与范围。
2. 验证健康状态、认证和允许的来源。
3. 测试完整的结构化工具调用闭环。
4. 检查实时能力注册表。
5. 持久化热数据库与 checkpoint。
6. 定义审批者与取消权限。
7. 在整个行动中审查证据、工具和参数。

## 部署

已验证路径是 GitHub Actions 上的适配器 Discord 与 DeepSeek V4-Flash。Web GUI 在修复循环
通过后加入。临时 runner 需要通过 artifact
或远程存储显式持久化。生产环境需要持久卷、受保护入口、强秘密、严格来源和保留策略。

## 安全模型

服务器控制身份、策略、审批与运行状态。网页内容、提供商结果和 Hugin 卡片均是不可信数据。
生成能力必须经过验证并遵守与原生工具相同的策略边界。工具调用成功并不能证明已获授权或
任务已经成功。

## 许可证

Munin 使用 PolyForm Noncommercial 1.0.0。许可范围内的非商业研究和学习可以进行；
商业产品、服务、咨询和内部商业应用需要单独许可证。
