# Munin — architecture

## 30-second overview

Munin is a **ReAct agent** with a soul (Markdown files) and a memory (shared SQLite),
that coordinates a set of subagents through the **OFFX-MCP** it absorbed and extended.
Subagents can be woken on demand, run in their own subprocess, and go back to sleep.
Munin can **forge** two new things at runtime: **Python tools** (`tool_forge`) and
**entire ReAct subagents** (`graph_forge`).

## Data flow

1. Human types a request → `MuninAgent.respond(...)` in `munin/core/munin_agent.py`.
2. Munin composes system prompt from soul + memory summary + generated tools catalog.
3. Sends messages + tool specs (auto-generated from function signatures) to LLM via `LLMClient`.
4. LLM replies with either text OR tool calls. On tool call, Munin dispatches to the
   underlying Python function (native MCP tools + `gen__*` autogenerated).
5. Each step is logged to `episodic` in shared state — visible to any subagent.
6. When Munin decides to delegate ("spawn a specialist"), it calls `munin_wake(name, task)`.
   `Orchestrator` enqueues the task in `agent_wake_queue`, spawns
   `python -m munin.subagents.runner <name>` as a detached subprocess. That subprocess
   claims the wake item, executes it, posts the result to `agent_messages`, and exits
   when the queue drains + idle timeout expires.

## Persistence topology (single SQLite file)

All state lives in `data/shared_state.sqlite`:

| Table              | Origin       | Purpose                                           |
| ------------------ | ------------ | ------------------------------------------------- |
| `shared_intel`     | OFFX legacy  | Findings shared across agents                     |
| `active_tasks`     | OFFX legacy  | Exclusive task locks with leases                  |
| `agent_presence`   | OFFX legacy  | Who's awake, IDLE, or stale                       |
| `agent_messages`   | OFFX legacy  | Inter-agent inbox                                 |
| `episodic`         | Munin new    | Every tool call, ReAct step, decision             |
| `semantic`         | Munin new    | Facts Munin remembers (`memory_remember/recall`)  |
| `procedural`       | Munin new    | Autogenerated tool registry (`gen__*`)            |
| `generated_graphs` | Munin new    | Forged ReAct subagent configurations              |
| `agent_wake_queue` | Munin new    | Orchestrator → subagent wake channel              |

## The forging loop

```
   spec ──► tool_forge subagent (LLM)
              │
              ▼
   [candidate .py]
              │
              ▼
   AST guard (imports allow-list, __class__/exec/eval blocked)
              │
              ▼
   sandbox exec (restricted __builtins__, timeout, jailed cwd)
              │
      ok ────► registry.register → gen__<slug> hot-loaded on MCP
              │                    procedural row inserted
     fail ────► feedback → next iteration
```

## Reset semantics

`munin reset`:
1. Purge `procedural` + delete `.py` scripts in `munin/generated/`.
2. Purge `generated_graphs` rows where `reset_policy = 'on_reset'`.
3. Wipe `episodic`, `semantic`, `agent_wake_queue`.
4. Restore `soul/` from `data/soul.snapshot.json` (removes drift files).
5. Clear `data/soul_pending/`.

Idempotent: safe to run repeatedly.
